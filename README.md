# Kali Deck · 全工具中文分类工作台

最新版默认进入“新手模式”，提供25个按任务组织的三步引导、一个无需安装软件的演示，以及只读的文件格式识别与下一步建议。工具大标题改为唯一原始名称，11个跨包同名命令在界面中合并显示，保留来源切换；详见 `docs/新手使用.md`。CTF专用预设扩充后为74项，完整官方登记仍保留。

中文版已将781个官方目录条目划分为25个中文用途分类，支持中文功能词搜索、中文功能标签与常用参数标签。工具原名保留用于核对和运行，第三方窗口及原始帮助保留原文。安装状态区分软件包和程序入口，检测失败不会再被视为未安装。新包为 `dist/Kali-Deck-Chinese.zip`，详见 `docs/中文版说明.md`。

本版范围已扩为 Kali 官方 all-tools 目录中的全部 781 个条目。新增全工具页，登记 1382 个包安装入口和 2751 个程序执行入口，其中 1919 个程序有从官方帮助文本生成的选项表单。首页默认打开新手模式，74个 CTF/AWDplus 专用预设位于“CTF 精选”。平台单人本地运行，不接入 AI，运行只依赖 Python 3.10+ 标准库，不需要 Node 或 CDN。

## GitHub 解题精选

新增RsaCtfTool、xortool、bkcrack、angr、Volatility 3和oletools的12个专用功能，按题型分组并附准备材料、安装按钮和结果阅读提示。GitHub精选页还有复用的pwntools、ROPgadget、zsteg、Stegseek；CyberChef和Ciphey明确标为参考链接。安装使用项目独立环境，源码固定提交并校验；详细能力边界与实际检查结果见 [GitHub解题工具与检查结果](docs/GitHub解题工具与检查结果.md)。

## 从 GitHub 获取

在本仓库点击绿色 **Code → Download ZIP**，将源码ZIP传到Kali并完整解压，然后双击`启动工具台.desktop`。平台本身无需安装Python第三方依赖；Kali需有Python 3.10+与桌面环境。Git源码包不含大型第三方源码快照，缺少的可选安装资料会在点击“安装工具”时下载固定版本并校验SHA-256，无需输入命令。

维护者生成完整离线资料分发包前，先运行`python scripts/fetch_artifacts.py --all`，再运行`python scripts/package.py`。这只准备工具源码资料，安装依赖仍可能需要联网。

平台代码采用[MIT许可证](LICENSE)，第三方目录、帮助文本和工具保留各自许可，详见[第三方说明](THIRD_PARTY.md)。仅对自己的CTF题目、本地文件和已获授权的比赛环境使用。

## 在 Kali 上启动

将整个文件夹复制到 Kali 的用户目录，或者将 `dist/Kali-Deck-Chinese.zip` 复制到 Kali 后使用归档管理器完整解压。不要只复制启动图标。

双击文件夹中的 `启动工具台.desktop`。首次启动时，文件管理器可能要求选择“允许启动”或“信任并启动”；若显示为文本文件，使用文件属性中的“权限”页启用“允许作为程序执行”，再双击。启动器通过桌面规范的 `%k` 定位自身所在目录，支持中文和空格路径。浏览器随后打开 `http://127.0.0.1:8765`。这不是需要输入的命令，只是本地网页地址。

在工具中心选择一个功能，按表单上传文件或填写比赛地址，然后点击“一键执行”。首次可用“常见编码转换”验证平台能正常工作。文件超过 256 MiB 时，填写其在 Kali 上的绝对路径，不必通过浏览器上传。

缺少系统工具时，点击“安装工具”，在 Kali 自带的系统授权窗口确认，平台通过 `pkexec apt-get install` 安装登记的固定软件包。平台进程无需以 root 身份运行。更新按钮更新该软件包，不会自动刷新整个系统的软件索引。如果提示包不存在、索引过期或软件源错误，使用 Kali 的图形软件管理器刷新软件源，之后重试；不要在 Windows 开发预览中尝试安装 Kali 工具。图形授权需要正在运行的桌面 Polkit agent。

40 个不同的 APT 包名已对照 Kali rolling 官方 amd64 软件索引确认存在，结果保存在 `resources/kali-packages.json`；Nikto 位于 non-free 组件。OutGuess 与 zsteg 没有对应的当前仓库软件包，改用专门安装器：先通过系统授权安装固定的构建依赖，再以普通用户身份在项目 `data/vendor` 中构建 OutGuess 或安装 zsteg RubyGem。OutGuess ZIP 固定到上游提交，zsteg 固定为收集时的 RubyGem 版本，均有 SHA-256 清单。安装资料位于 `resources/optional`，仅在 Kali 中点击安装按钮时解压或执行；zsteg 的依赖由 RubyGems 在线解析。可选安装器的完整构建过程尚需 Kali 实机验证。

“任务与结果”中可以查看实时日志、停止任务、下载结果。图形工具如 Burp、Ghidra、Wireshark 会另开窗口，关闭后任务结束，最长时限见参数面板。帮助窗口中有关闭平台的按钮；关闭浏览器页面不会停止后台任务。不要在任务运行时移动项目文件夹。

## 集成范围与真实状态

`ctfhub/catalog.py` 登记已经接入执行表单的功能，包含平台内置操作、调用系统命令的适配器和独立 GUI 启动入口。系统命令使用 Kali 自己的软件包路径；将整个 Kali 系统的软件二进制复制进项目会破坏依赖管理，因此软件通过 Kali 包管理器安装，平台代码、工具清单、上游资料、源码快照和执行结果保存在此文件夹。

`resources/kali-index.json` 保留官方索引。`resources/kali-full.json` 包含全部 781 页采集结果、包与程序对应关系、原始帮助和推断选项。它们接入全工具管理和执行接口，不再只是链接目录。选项类型由文档推断，需要用户核对；2751 个登记入口不代表2751个程序都在Kali上实测通过。`resources/sources.json` 保存选定 GitHub 项目的上游地址、提交版本、许可证、归档状态和收集结果。`resources/upstream/` 保存 README、能找到的许可证及部分项目的完整源码 ZIP；ZIP 固定到提交 SHA，并在清单记录 SHA-256，但不是 Kali 的已安装二进制。第三方源码保留其自身许可证，未自动构建或执行安装脚本。

AWDplus 内置入口包括本机源码 ZIP 备份、SHA-256 基线、文件变化对比、源码可疑特征定位、服务可达性检查、Flag 文本提取与去重。源码检查只提供规则匹配线索；服务检查是手动触发的一次检查。Flag 不自动提交，平台不内置自动攻击循环、自动修补或靶机部署。AoiAWD、AWD-Guide、JarPatcher 等以源码资料形式收集，未声称完成其一键部署。不同比赛的靶机、补丁接口和 Flag 提交协议不同，应另加专门适配。

用户可直接使用固定预设。逆向调试、复杂密码学、交互式利用等操作仍需要对应的专业工具知识，平台不声称一键自动解出所有题目。全网工具不存在稳定、可验证的全集，这个项目提供官方目录索引、已适配工具和可继续扩充的登记结构。

## 数据与运行限制

平台仅监听 `127.0.0.1`，不开放远程访问。请求检查 Host、Origin 和启动时生成的会话令牌；所有程序使用参数数组执行，不使用 Shell 拼接，不接受任意命令输入。上传文件和结果日志可能包含题目、密码或 Flag，保存在 `data/`，不要将此目录打包分享。

可选安装器会以参数数组调用上游自带的固定构建脚本，只有依赖软件包安装经过系统提权；不提权执行项目中的 Python 或第三方源码脚本。解压检查目录穿越、符号链接与总解压大小。源码备份、基线和变化对比支持嵌套目录，跳过输出目录，避免把自己生成的结果反复加入。

最多同时运行四个任务；普通任务有超时和停止按钮，系统安装不会被平台强制中止。CLI 日志超过 16 MiB 会停止任务。内置文本操作单文件最大 64 MiB，目录扫描最多 20000 个文件，ZIP 备份最大 1 GiB；目录扫描跳过符号链接与平台数据目录。可用空间由操作系统管理，结果文件需自行定期清理。软件包安装可能受系统权限、镜像、架构、包名变化和外部设备驱动影响；安装失败会保留真实日志，不伪装成成功。

## 开发与扩充

添加命令适配器时，在 `ctfhub/catalog.py` 中登记字段类型、固定参数数组、可执行文件和 Kali 软件包。添加内置功能时，在 `ctfhub/operations.py` 中实现并登记字段。禁止增加自由拼接命令的输入框。前端为本地 HTML/CSS/JavaScript，避免新手还需要配置前端构建环境。

维护者可用 `python -m ctfhub.server --no-browser` 启动调试，用 `python -m unittest discover -s tests -v` 运行测试，用 `python scripts/package.py` 重新生成分发包。用户日常操作无需使用这些命令。`scripts/collect_sources.py` 更新上游文档和官方索引，`scripts/download_archives.py` 获取选定版本源码；这些联网维护脚本不在平台启动时自动运行。

## 全工具页的使用与覆盖边界

按官方分类、名称或本机检测状态筛选，点击包名安装或更新。点击某个程序，选择文档选项，填写参数值；可通过“有值”复选框纠正选项类型。文件通过选择器上传，子命令、目标或其他位置参数按顺序逐行填写；位置参数与选项顺序可以切换。没有自由 Shell 命令框，选项名称必须来自该程序的登记清单。

运行方式包括保存输出的表单任务、带回复输入框的交互会话、独立图形窗口。Linux 交互会话使用 PTY，Windows 开发测试使用管道。命令行界面的交互功能仍然需要理解工具自己的提示；这不是对所有工具业务界面的逐个重写。对于需要系统权限的操作，可以勾选系统授权运行，密码只交给系统授权窗口。提权进程由系统管理，平台不会强杀，需要先在工具里退出后再关闭平台。

对已经安装的软件包，可以点击“发现图形入口”，读取该包拥有的 .desktop 文件并通过系统 gio 启动，不能提交任意桌面文件路径。官方页没有列出程序的 33 个条目包括组件/数据包/元包，以及 top-100 导航页；仅在有官方包名时提供安装按钮，不伪造可执行程序。分类标签来自官方分类首页，首页未分类的条目标为“其他工具与组件”。

软件安装由 Kali 的 APT 实际解析架构、当前镜像、依赖与许可组件。本版不会启动时批量安装全部软件，不会复制几十 GB Kali 二进制。数据库初始化、硬件/驱动配置、许可证、服务向导等无法从帮助文本推导，需依照对应官方说明完成。可用表单覆盖与逐工具实机验证是两项不同工作；完整范围和验证限制见 docs/全工具覆盖说明.md。
