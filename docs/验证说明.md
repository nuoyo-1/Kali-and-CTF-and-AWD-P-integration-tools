# 交付验证说明

验证日期为 2026 年 11 月 23 日。本版本在 Windows 开发环境完成平台逻辑、接口和真实浏览器验证，交付给用户复制到 Kali 后实测。第三方源码 ZIP 和 RubyGem 在 Windows 中仅保存、读取元数据与校验，未解压执行。

## 已完成的验证

29 项 Python 自动测试全部通过，覆盖内置编码、二进制输出、文件哈希、熵分析、ZIP 目录查看、Flag 去重、源码规则定位、嵌套目录基线、变化对比、备份、任务取消与超时、上传到执行再到下载的完整接口流程、历史恢复、Host/Origin/会话校验、表单参数校验、目录选择，以及可选安装器解压时的路径穿越和符号链接拒绝。

真实 Chrome 浏览器测试通过：61 个功能入口加载、桌面与手机尺寸无横向溢出、编码转换任务一键执行成功、日志包含预期结果、结果文件列表正常、搜索过滤正常、目录选择回填正常、781 条官方目录和 20 个上游项目资料加载正常。测试未发现 JavaScript 异常。截图保存在 `docs/preview.png` 和 `docs/preview-mobile.png`。

Python 编译检查、前端 JavaScript 语法检查通过。打包脚本在生成分发包前检查收集的 README、源码 ZIP、可选安装资料 SHA-256 和 ZIP CRC，并验证平台 Python 文件语法。分发包不包括本地 data 目录，也不包括散落的 PHP 源码；第三方源码继续保存在嵌套的 ZIP 内。分发包内部含 MANIFEST.json，外部另有整体 SHA-256 文件。

对照 Kali 官方 rolling 的 amd64 主仓库、contrib、non-free 和 non-free-firmware 索引核实了 40 个不同 APT 包。Nikto 属于 non-free；OutGuess 与 zsteg 改用独立安装器。这项检查确认包名存在，不等于每个工具已经完成实际运行测试，也不保证其他架构的软件包情况。

## 需要 Kali 实机验收的部分

桌面启动器的文件信任流程与中文路径、默认浏览器自动打开、系统 Polkit 授权弹窗、APT 安装及软件源状态、OutGuess 构建和 zsteg Ruby 依赖安装、各 CLI 工具在实际题目上的参数兼容性、独立 GUI 窗口启动、Hashcat 的计算驱动、Linux 下进程组停止，均需在用户的 Kali 桌面环境中验证。不能用 Windows 中 PATH 检测到的可执行文件代表 Kali 上的验证结果。

## 建议的验收顺序

先解压并双击启动器，运行内置编码转换，再上传 samples/示例日志.txt 提取两个不同 Flag。随后用 samples/基线演示 创建基线、备份，修改子目录里的演示文本后执行变化对比。最后挑选各类别中已安装的工具测试，缺少工具时点安装，查看系统授权和实际日志。

验证命令只供维护者复查，平台使用者无需手工输入：Python 测试为 `python -m unittest discover -s tests -v`，浏览器测试为启动平台后运行 `node scripts/browser_check.mjs`。浏览器测试使用独立的 Chrome 测试配置目录，Linux 可自动寻找 Chromium/Chrome，也可通过 CHROME_PATH 指定路径；Node 仅为开发测试依赖，平台运行不需要 Node。
